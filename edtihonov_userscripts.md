[ Сценарий 1 - Первый запуск и регистрация преподавателя ]
1.	Преподаватель разворачивает приложение: запускает Docker-контейнер командой docker compose up или запускает бинарный файл для своей ОС.
2.	В терминале появляется сообщение об успешном старте сервера с указанием локального адреса (например, http://localhost:15732).
3.	Преподаватель открывает браузер и переходит по указанному адресу. Система обнаруживает, что база данных пуста, и автоматически перенаправляет на страницу первоначальной настройки.
4.	Преподаватель вводит желаемый логин, пароль и, опционально, отображаемое имя.
5.	Если введённый пароль содержит менее 8 символов, система выводит предупреждение и просит ввести более надёжный пароль.
6.	После успешного заполнения формы система создаёт единственную учётную запись с ролью "Администратор / Преподаватель" и сообщает, что первоначальная настройка завершена.
7.	Система автоматически выполняет вход и перенаправляет преподавателя на главный дашборд. Отображается краткое приветственное сообщение с подсказкой о первом шаге: "Создайте свой первый вопрос".
8.	Запускается Сценарий 2 - Создание вопроса.

[ Сценарий 2 - Создание вопроса ]
1.	Преподаватель находится на главном дашборде и нажимает кнопку "Создать вопрос" (или переходит в раздел "Банк вопросов" и нажимает "+").
2.	Открывается страница редактора вопроса. Страница разделена на две панели: левая - редактор ввода, правая - живой предпросмотр вопроса в том виде, в каком его увидит студент.
3.	Преподаватель вводит условие задания в единое текстовое поле. Поле поддерживает смешанный контент:
 ∙	Обычный текст и Markdown (жирный, курсив, списки, заголовки).
	∙	Математические формулы в синтаксисе LaTeX (например, $E = mc^2$ или блочные формулы $$\int\_{a}^{b} f(x)dx$$ или используя встроенный графический редактор). Формулы мгновенно отрисовываются в предпросмотре через KaTeX.
	∙	Фрагменты кода в блоках с указанием языка (например, ```cpp). Подсветка синтаксиса применяется мгновенно через CodeMirror.
4.	Преподаватель выбирает тип вопроса из выпадающего списка. Доступны следующие типы:
	∙	Один правильный ответ (radio).
	∙	Несколько правильных ответов (checkbox).
	∙	Свободный ответ (текстовое поле).
	∙	Числовой ответ.
	∙	Установление соответствия.
	∙	Упорядочивание последовательности.
5.	В зависимости от выбранного типа нижняя часть редактора меняется, предлагая соответствующий интерфейс для заполнения вариантов ответа и указания правильных.
6.	Если выбран тип "Один/несколько правильных ответов": преподаватель добавляет варианты ответа кнопкой "Добавить вариант" и отмечает правильный(е). Каждый вариант ответа также поддерживает LaTeX и код.
7.	Если выбран тип "Свободный ответ": преподаватель может указать эталонный ответ или регулярное выражение для автоматической проверки (поле "Шаблон проверки"). Рядом с полем располагается кнопка "Проверить шаблон", позволяющая ввести тестовую строку и убедиться, что шаблон работает корректно.
8.	Если выбран тип "Числовой ответ": преподаватель вводит правильное число и допустимую погрешность (абсолютную или относительную).
9.	Если выбран тип "Установление соответствия": преподаватель добавляет пары "левый элемент - правый элемент" и может перемешать их порядок.
10.	Если выбран тип "Упорядочивание": преподаватель добавляет элементы списка, которые студент должен расставить в правильном порядке.
11.	Преподаватель указывает количество баллов за вопрос (по умолчанию - 1).
12.	Преподаватель опционально добавляет теги (например, "механика", "Golang", "линейная алгебра") для удобной фильтрации в банке вопросов.
13.	Преподаватель нажимает кнопку "Сохранить". Если обязательные поля (условие и хотя бы один правильный ответ) не заполнены, система выделяет пустые поля и выводит сообщение об ошибке, не закрывая страницу.
14.	Если все данные корректны, вопрос сохраняется в банке вопросов. Система предлагает два действия: "Создать ещё один вопрос" или "Перейти в банк вопросов".

[ Сценарий 3 - Управление банком вопросов ]
1.	Преподаватель переходит в раздел "Банк вопросов". На экране отображается список всех созданных вопросов в виде карточек.
2.	Каждая карточка показывает: краткое условие вопроса (с отрисованными формулами), тип вопроса, теги, количество баллов и дату создания.
3.	Преподаватель может отфильтровать список по тегам, типу вопроса или выполнить текстовый поиск по условию.
4.  При нажатие на знак "+" преподаватель может импортировать вопросы в формате .md .
5.	При нажатии на карточку вопроса открывается его полный предпросмотр с возможностью перейти к редактированию или удалению.
6.	Если преподаватель нажимает "Редактировать", открывается редактор вопроса (Сценарий 2), предзаполненный текущими данными вопроса.
7.	Если преподаватель нажимает "Удалить", система запрашивает подтверждение и предупреждает, что вопрос будет удалён из всех тестов, в которые он входит (Каскадное удаление).
8.	Если преподаватель подтверждает удаление, вопрос удаляется. Если отменяет - возвращается к карточке вопроса.
9.	Преподаватель может выбрать несколько вопросов (чекбоксами) и выполнить групповые действия: добавить в тест или удалить.
10.	Запускается Сценарий 4 - Создание теста.

[ Сценарий 4 - Создание теста ]
1.	Преподаватель переходит в раздел "Тесты" и нажимает кнопку "Создать тест".
2.	Открывается страница настроек теста. Преподаватель вводит название теста и опциональное описание.
3.	Преподаватель задаёт параметры прохождения:
	∙	Ограничение по времени (поле ввода в минутах; если оставить пустым - время не ограничено).
	∙	Количество допустимых попыток (по умолчанию - 1; можно задать неограниченное количество).
	∙	Показывать ли студенту правильные ответы после завершения (переключатель).
	∙	Перемешивать ли порядок вопросов для каждого студента (переключатель).
4.	Преподаватель переходит к шагу "Добавить вопросы". Открывается панель с банком вопросов (с фильтрацией и поиском), из которой он перетаскивает или выбирает нужные вопросы.
5.	Добавленные вопросы отображаются в упорядоченном списке. Преподаватель может вручную изменить их порядок перетаскиванием или убрать конкретный вопрос из теста (без удаления из банка).
6.	Если преподаватель пытается сохранить тест без единого вопроса, система выводит предупреждение и не позволяет сохранить.
7.	Преподаватель нажимает "Сохранить тест". Тест сохраняется со статусом "Черновик" и появляется в списке тестов.
8.	Запускается Сценарий 5 - Запуск теста.

[ Сценарий 5 - Запуск теста и получение ссылки ]
1.	Преподаватель находится в списке тестов или на странице конкретного теста и нажимает кнопку "Запустить тест".
2.	Система генерирует уникальный сеанс (сессию) прохождения и переводит тест в статус "Активен".
3.	На экране крупно отображается:
	∙	Короткая ссылка-приглашение (например, http://192.168.1.5:15732/join/xK7q2Dckx).
	∙	QR-код, ведущий по той же ссылке.
	∙	Кнопка "Скопировать ссылку".
4.	Преподаватель демонстрирует QR-код студентам (через проектор или отправляет ссылку в чат).
5.	По мере того, как студенты присоединяются, на экране преподавателя в реальном времени обновляется список участников: отображаются их имена (или псевдонимы) и статус ("Ожидает", "Проходит", "Завершил").
6.	Преподаватель может принудительно завершить сессию в любой момент, нажав "Завершить сессию". При этом система запрашивает подтверждение, предупреждая, что ответы всех активных участников будут зафиксированы как есть.
7.  преподаватель может принудительно завершить сессию для *одного* участника, наведясь на него в списке и нажав "Завершить сессию для ${псевдонимУчастника}". При этом система запрашивает подтверждение, предупреждая, что ответы выбранного участника будут зафиксированы как есть.
8.	После того как последний участник сдаёт тест (или истекает время), система автоматически переводит сессию в статус "Завершена".
9.	Система предлагает перейти к результатам. Запускается Сценарий 7 - Просмотр результатов и аналитики.

[ Сценарий 6 - Прохождение теста студентом ]
1.	Студент получает ссылку или QR-код от преподавателя и переходит по ней в браузере.
2.	Открывается страница входа в сессию. Студент вводит своё имя (или псевдоним) - регистрация в системе не требуется.
3.	Если сессия ещё не запущена преподавателем, студент видит экран ожидания: "Ожидайте начала теста. Преподаватель скоро запустит сессию".
4.	Как только преподаватель запускает сессию, студент автоматически (без перезагрузки страницы) попадает на первый вопрос теста.
5.	Если тест имеет ограничение по времени, в верхней части экрана отображается таймер обратного отсчёта.
6.	Студент видит вопрос с полностью отрисованными формулами и подсветкой синтаксиса кода. Интерфейс адаптивен и одинаково удобен как на компьютере, так и мобильном устройстве.
7.	Студент выбирает или вводит ответ. Ответы автоматически сохраняются - если студент случайно закрыл вкладку и вернулся по той же ссылке, его прогресс сохранён.
8.	Студент переходит между вопросами кнопками "Назад" / "Далее" или через панель навигации с номерами вопросов. Отвеченные вопросы отмечаются визуально.
9.	На последнем вопросе появляется кнопка "Завершить тест". При нажатии система запрашивает подтверждение: "Вы уверены? Вы ответили на K из V вопросов".
10.	Если студент подтверждает, ответы отправляются, тест закрывается.
11.	Если преподаватель разрешил показ результатов, студент сразу видит свой результат: количество набранных баллов, процент правильных ответов и, в зависимости от настроек, - свои ответы рядом с правильными.
12.	Если преподаватель запретил показ результатов, студент видит нейтральное сообщение: "Ваши ответы приняты. Результаты объявит преподаватель".
13.	Если истекает таймер до того, как студент нажал "Завершить", система автоматически фиксирует все введённые к этому моменту ответы и переводит тест в статус завершённого.

[ Сценарий 7 - Просмотр результатов и аналитики ]
1.	Преподаватель переходит на страницу результатов завершённой сессии (из списка сессий или по предложению системы после завершения).
2.	Страница результатов содержит сводную информацию: название теста, дата проведения, количество участников, средний балл, минимальный и максимальный балл.
3.	В первой вкладке "Участники" отображается таблица: имя студента, набранный балл, процент, время завершения, статус попытки.
4.	Преподаватель может нажать на строку конкретного студента и развернуть детальный просмотр его ответов: каждый вопрос, ответ студента, правильный ответ, статус ("Верно" / "Неверно" / "Частично верно").
5.	Во второй вкладке "Статистика по вопросам" для каждого вопроса показывается: процент студентов, ответивших верно, распределение выбранных вариантов ответа (в виде диаграммы), средний балл за вопрос.
6.	Если процент правильных ответов на вопрос ниже порогового значения (например, 50%), вопрос визуально выделяется как "проблемный" - это сигнал преподавателю, что материал усвоен плохо.
7.	Преподаватель нажимает кнопку "Экспортировать" и выбирает формат - CSV. Система формирует файл, содержащий таблицу результатов всех участников, и скачивает его в браузере.
8.	Если преподаватель хочет провести повторное тестирование по тем же вопросам, он нажимает "Запустить новую сессию" - система создаёт новую сессию на основе того же теста. Запускается Сценарий 5 - Запуск теста.​​​​​​​​​​​​​​​​

[ Сценарий 8 - Экспорт и импорт банка вопросов ]
1.	Преподаватель или методист переходит в раздел "Банк вопросов" и нажимает кнопку "Экспортировать".
2.	Система предлагает выбрать область экспорта: весь банк вопросов целиком или только отфильтрованная выборка (по тегам, типу вопроса, конкретному тесту).
3.	Преподаватель выбирает нужную область и подтверждает действие. Система формирует файл в открытом текстовом формате (JSON) и скачивает его в браузере.
4.	Структура файла прозрачна и читаема: каждый вопрос представлен самостоятельным объектом с полями условия, типа, вариантов ответа, правильных ответов и тегов. Такой формат позволяет хранить файл в Git-репозитории, отслеживать изменения и делиться банками вопросов с коллегами через привычные инструменты (GitHub, GitLab, CodeBerg и т.д.).
5.	Для импорта преподаватель нажимает кнопку "Импортировать" в том же разделе и выбирает JSON-файл на своём компьютере.
6.	Система анализирует файл. Если формат файла не соответствует ожидаемой схеме, выводится сообщение об ошибке с указанием, какие поля отсутствуют или заполнены некорректно. Импорт не выполняется.
7.	Если файл корректен, система отображает предпросмотр: список вопросов, которые будут импортированы, и предупреждение о том, сколько из них конфликтует с уже существующими (определяется по совпадению условия и типа).
8.	Преподаватель выбирает стратегию обработки конфликтов: "Пропустить дубликаты", "Заменить существующие", "Добавить все как новые" и "Переименовать конфликтующие".
9.	После подтверждения вопросы добавляются в банк. Система выводит итоговое сообщение: сколько вопросов добавлено, сколько пропущено или заменено.
10.	Преподаватель возвращается к банку вопросов и видит импортированные вопросы в общем списке. При необходимости он может отфильтровать их по тегам, которые пришли вместе с импортированным файлом.

[ Сценарий 9 - Настройка профиля и параметров системы ]
1.	Преподаватель нажимает на своё имя или аватар в правом верхнем углу интерфейса. Открывается выпадающее меню с пунктами "Профиль", "Настройки системы" и "Выйти".
2.	Преподаватель переходит в раздел "Профиль".
3.	На странице профиля отображаются текущие данные учётной записи: логин и отображаемое имя. Преподаватель может изменить отображаемое имя и нажать "Сохранить".
4.	Для смены пароля преподаватель нажимает "Изменить пароль". Открывается форма с тремя полями: "Текущий пароль", "Новый пароль", "Повторите новый пароль".
5.	Если текущий пароль введён неверно, система выводит сообщение об ошибке и не применяет изменения.
6.	Если новый пароль содержит менее 8 символов, система предупреждает о требованиях к длине.
7.	Если поля "Новый пароль" и "Повторите новый пароль" не совпадают, система указывает на несоответствие.
8.	При успешном прохождении всех проверок пароль обновляется. Система выводит подтверждение: "Пароль успешно изменён".
9.	Преподаватель переходит в раздел "Настройки системы".
10.	На странице настроек доступны следующие параметры:
∙	Язык интерфейса (например, Русский / English).
∙	Тема оформления (светлая / тёмная / системная(прим: система = браузер пользователя)).
∙	Значение по умолчанию для лимита времени новых тестов.
∙	Показывать ли студентам результаты по умолчанию (глобальный переключатель, который можно переопределить на уровне конкретного теста).
11.	Преподаватель вносит нужные изменения и нажимает "Сохранить настройки". Система применяет изменения немедленно, без перезагрузки страницы.
12.	Если преподаватель нажимает "Выйти" в выпадающем меню, сессия завершается и он перенаправляется на страницу входа.

[ Сценарий 10 - Прохождение теста с несколькими попытками ]
1.	Преподаватель при создании или редактировании теста (Сценарий 4) устанавливает количество допустимых попыток больше единицы (например, 3) или выбирает значение "Неограниченно"(что очень щедро).
2.	Студент проходит тест и завершает первую попытку. Система фиксирует результат первой попытки и отображает его студенту (если это разрешено настройками теста).
3.	На странице результата отображается кнопка "Пройти ещё раз", если у студента остались доступные попытки. Рядом с кнопкой указано: "Использовано попыток: 1 из 3".
4.	Студент нажимает "Пройти ещё раз". Если тест настроен с перемешиванием вопросов, система формирует новую последовательность. Студент начинает новую попытку с чистого листа - предыдущие ответы не отображаются и не влияют на текущий ввод.
5.	По завершении второй и последующих попыток студент снова видит результат. На экране дополнительно отображается сравнительная строка: "Лучший результат из всех попыток: X баллов (попытка N)".
6.	Если студент исчерпал все допустимые попытки, кнопка "Пройти ещё раз" заменяется сообщением: "Вы использовали все доступные попытки". Возможность повторного прохождения заблокирована.
7.	На стороне преподавателя в таблице результатов (Сценарий 7) для каждого студента отображаются все его попытки в виде раскрывающегося списка. По умолчанию в сводной таблице учитывается лучший результат из всех попыток, однако преподаватель может переключиться на режим "Последняя попытка" с помощью соответствующего переключателя над таблицей.
8.	При экспорте результатов в CSV каждая попытка каждого студента выгружается отдельной строкой с указанием номера попытки, баллов и времени завершения.

[ Сценарий 11 - Создание и проведение контеста ]
1.	Преподаватель переходит в раздел "Контесты" и нажимает кнопку "Создать контест".
2.	Преподаватель вводит название контеста и опциональное описание. Контест представляет собой объединение нескольких тестов в одну последовательную сессию с единым итоговым результатом.
3.	Преподаватель добавляет тесты в контест из списка уже созданных тестов. Тесты отображаются в виде карточек с названием и количеством вопросов. Преподаватель выбирает нужные и устанавливает их порядок перетаскиванием.
4.	Для каждого теста внутри контеста преподаватель может переопределить локальный лимит времени (независимо от глобальных настроек теста). Например, первый тест - 10 минут, второй - 20 минут.
5.	Преподаватель настраивает поведение контеста: разрешить ли студенту возвращаться к предыдущему тесту после его сдачи или блокировать переход назад.
6.	Преподаватель нажимает "Сохранить контест". Контест сохраняется со статусом "Черновик".
7.	Для запуска преподаватель нажимает "Запустить сессию контеста". Система генерирует единую ссылку и QR-код для входа (аналогично Сценарию 5).
8.	Студент, перейдя по ссылке и введя имя, последовательно проходит тесты, входящие в контест. После завершения каждого теста он видит промежуточный результат за этот тест и кнопку "Перейти к следующему тесту".
9.	Если у студента истекает время на отдельный тест, система автоматически фиксирует его ответы и переводит его к следующему тесту без дополнительных действий.
10.	По завершении всех тестов студент видит итоговый экран контеста: суммарный балл по всем тестам, разбивку по каждому тесту в виде таблицы, итоговый процент выполнения.
11.	На стороне преподавателя страница аналитики контеста (аналогично Сценарию 7) отображает: сводную таблицу участников с итоговыми баллами и разбивкой по тестам, статистику по вопросам в разрезе каждого теста отдельно. Экспорт в CSV доступен как по всему контесту, так и по отдельному тесту внутри него.​​​​​​​​​​​​​​​​
